# crowdsense-backtest

**CrowdSense 인파밀집 예측의 정확도를 검증하기 위한 관측 데이터 수집소**입니다.

CrowdSense는 서울 실시간 도시데이터를 받아 인파밀집 위험을 예측하는 관제 서비스입니다
([데모](https://crowdsense-jvv1.vercel.app) · 제4회 재난안전데이터 활용 창업경진대회 최우수상).
이 저장소는 그 서비스의 **공개 API를 주기적으로 호출해 예측과 실측을 같은 시간축에 쌓습니다.**
제품 소스 코드는 들어 있지 않습니다.

## 왜 따로 쌓는가

"예측이 실제로 몇 % 맞았나"에 답하려면, 예측한 시점의 판단과 그 이후에 실제로 일어난 일이
같은 시간축 위에 있어야 합니다. 서울시 API는 현재 상태만 주고 과거를 돌려주지 않으므로,
지나가는 순간을 그때그때 적재해 두지 않으면 나중에 검증할 방법이 없습니다.

## 무엇이 쌓이나

`backtest/YYYY-MM-DD.jsonl` — 한 줄이 한 시점의 전체 감시지점(서울 32곳) 스냅샷입니다.

| 항목 | 내용 |
|---|---|
| 관측 | 혼잡 등급, 추정 밀도, 경보 단계, 체류 인원 범위, 관측 시각 |
| 예측 | 유입 추세(급증·증가·정체·감소·판정불가), 기준 창, 순유입률 구간, 가속 배수, 임계 도달 예상 |
| 비교 기준선 | 공급자(서울시) 자체 시간대별 혼잡 예보 |

원본이 5분 주기로 갱신되므로, 직전과 관측 시각이 같으면 적재하지 않습니다.
공급자 예보는 4시간치만 담습니다 — 상승 사건 소급 탐색이 최대 120분이라 그 이상은 쓰이지 않고,
12시간 곡선을 다 넣으면 용량의 절반을 예보가 차지합니다.

## 수집

`.github/workflows/collect.yml` 이 10분마다 `collect.mjs` 를 실행합니다.
수동 실행은 Actions 탭의 **Run workflow** 로 할 수 있습니다.

```bash
# 로컬에서 한 번 수집
node collect.mjs

# 로컬 개발 서버 대상
BASE=http://localhost:3000 node collect.mjs
```

## 평가

평가 스크립트(`scripts/backtest.mjs`)는 제품 저장소에 있습니다. 이 저장소를 받아 지정하세요.

```bash
git clone https://github.com/13JVV/crowdsense-backtest.git /tmp/bt
node scripts/backtest.mjs --dir /tmp/bt/backtest --out docs/backtest-report.md
```

측정 항목:

1. **커버리지** — 판정을 낼 수 있었던 관측의 비율. 공급자가 준 오차 구간이 변화량보다 커서
   유입 방향을 확정할 수 없던 경우(`판정불가`)를 포함해 분모로 잡습니다. 판정한 것만 세면
   적중률이 부풀려지기 때문입니다.
2. **방향 적중률** — 추세 판정이 30·60분 뒤 실제 혼잡 등급 변화와 일치한 비율.
   등급이 4단계뿐이라 대부분 구간에서 등급이 유지되므로, '유지'는 적중으로 세지 않고
   별도로 집계합니다.
3. **선행 시간** — 혼잡 등급이 실제로 오르기 몇 분 전에 신호가 떴는가.
   같은 사건에 대해 **서울시 자체 예보**를 비교 기준선으로 함께 측정합니다.
4. **오경보율** — '급증' 신호 중 확인 창 안에 실제 상승으로 이어지지 않은 비율.

## 데이터 출처

- [서울 열린데이터광장](https://data.seoul.go.kr/) 실시간 도시데이터 (`citydata`)
